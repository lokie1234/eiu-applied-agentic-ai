# Local course slide sources

`sources.json` binds each reviewed local section source to its course ID and section ID. The authenticated section content API uses this registry before reading an uploaded file. Web Development sections are compiled `Section1.js` / `Section2.js`: edit `storyboard.json` and the corresponding renderer in `web-app-development/`, then run `node scripts/build-web-app-course.cjs`. Display and download return the same local JS bytes. No Drive update is needed. Production sites require a deployment containing the changed files.

For a new course/section, add one registry entry with the verified `courseId`, `sectionId` from the database metadata, and a `path` under `course-content/<course>/`. Complete this binding whenever editing a section. Bindings use stable IDs, so renaming a course or exported file does not change its display source. Local files are private behind the existing course/section access checks. Missing registered files fail instead of displaying an outdated uploaded copy. Legacy uploaded TSX remains supported; do not restore TSX sources for compiled Web Development sections.

Save to Drive exports the same registered source that is displayed, verifies its bytes and leaves the local display binding unchanged, including when the export is renamed. Uploading a file to a registered section does not override its registered project source. To switch a registered section to an uploaded source, deliberately remove its local registry binding. Renaming course/section metadata does not affect ID-based bindings.
